# 現行決策與資料規則

- 保留 test／production 兩種模式，每次只寫一個目的地。兩者共用資料結構與寫入程式，送達進度分開。
- collector 使用專用 PostgreSQL 帳號直接寫入。執行帳密存於 `collector/.local/database/secrets/`，隨 collector 目錄搬移；schema 管理帳密留在專案根目錄的 `.local/database/secrets/`。
- 卡機只讀；不清紀錄、不校時、不修改使用者或讀取指紋範本。預設下載期間不停止員工打卡。
- 卡機以序號識別，帳號以字串保存並保留前導零。`employee_device_mapping` 按卡機與帳號連到目前對應的員工。
- 原始打卡只增不改；相同鍵保留原始內容，衝突交由人工查核。
- `punch_state` 與打在哪台機器都不作為上下班判定依據。後續出勤判定須結合班表，並保留人事人工調整。
- 驗證方式與狀態代碼按原值保存，不推定尚未確認的人事意義。
- 輪詢預設 5 分鐘；台北時間 03:30 完整下載並重送近 7 天資料。
- 本機主庫、測試庫及雲端資料庫預設時區皆為 `Asia/Taipei`；不以修改打卡資料來調整顯示時差。
- 已套用的 SQL migration 保留原文及 checksum；後續變更使用新版本。現行架構與操作以本專案 README、collector、database 與 architecture 文件為準。
- 職稱與職務分開，到職日、主管任期開始日與證照效期未知時留空。
- 專業證照的有效起迄包含當日。無期限需明確標記，空白日期不能判定有效。卡機帳號確認前的打卡保留目前候選員工並標為歷史待確認。
- 實際模式以 `.env` 為準，運行狀態以 Docker 查詢為準；文件不保存會隨時間變動的健康狀態或筆數。
