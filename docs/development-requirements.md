# WJCCH 人力資源系統開發需求規範

## 1. 目標與範圍

建立院內人資系統，讓員工可從 LINE 官方帳號或一般瀏覽器查詢及申請，讓主管在授權範圍內管理班表、處理案件與追查出勤異常。兩個入口共用同一套響應式網頁、後端 API、業務規則及資料。LINE 使用 Rich Menu，瀏覽器使用網頁選單。

本規範涵蓋上下班打卡與補簽、班表、調班及請假、職員與證照、簽核、報表、全院行事曆，以及串接各功能的待辦與通知。已確認的簽核規則以 [人事簽核流程開發規範](approval-workflow.md) 為準。本文件定義需求與驗收，不指定新增資料表的正式結構。

目前 `hr` 已有員工、部門、主管、職稱、職務、聘用類別、學歷、證照、卡機及原始打卡資料。`v_punch_employee` 提供打卡身分配對，`v_employee_license` 提供證照效期判定。登入授權、班表、申請、簽核、月結及通知屬後續實作。現有資料關係見 [人事資料與維護](../database/personnel/README.md)。

出勤作業從班表核准生效開始，依序經過打卡配對、異常發現、員工補正與主管簽核。核准後重算出勤與報表，已完成的月份依院方規則結算及更正。

## 2. 使用入口與權限

### 2.1 兩端共用

- LINE Rich Menu 開啟同一套網站的功能頁，瀏覽器可直接開啟相同頁面。兩端提交與查詢共用案件編號及狀態。LINE 專屬程式只處理登入銜接、Rich Menu 和訊息通知。 [LINE Rich Menu](https://developers.line.biz/en/docs/messaging-api/using-rich-menus/) · [LIFF 與外部瀏覽器](https://developers.line.biz/en/docs/liff/overview/)
- 選單依權限顯示操作入口。每次查詢、送件、匯出或簽核，後端都重新核對身分、操作權、資料範圍與案件狀態。直接開網址、修改參數或轉傳連結均受同一規則限制。
- 網頁開發須使用 Modern Web Guidance 搜尋及閱讀適用指引，並在交付前核對實作。動效依 [GSAP 官方技能](https://github.com/greensock/gsap-skills) 設計，支援減少動態效果設定及 React 卸載清理。開發工作要求見 [AGENTS.md](../AGENTS.md)。

### 2.2 帳號驗證與 LINE 綁定

- 兩種入口皆由後端驗證 LINE 登入憑證，並對應同一個 `employee_id`。員工帳號沿用 `employee_no`。首次綁定須比對身分證或居留證號及出生日期，由員工確認後建立一對一綁定。比對只用於當次驗證，系統不收集密碼或啟用碼。 [LINE 登入憑證驗證](https://developers.line.biz/en/docs/liff/using-user-profile/)
- 驗證 LINE 身分後開始綁定時，開啟 15 分鐘的驗證期限。每個 LINE 帳號跨裝置共用期限及失敗次數，第 5 次失敗後鎖定至原期限結束。在職及留職停薪期間可登入，離職後撤權。
- 要換綁 LINE 時，唯有系統管理者可解除既有綁定並留下操作紀錄，開放該員工再次比對員工資料及完成綁定。舊 LINE 帳號及依該綁定建立的登入須失去存取權。解除綁定的管理清單另行實作。
- 打卡、班表、申請與簽核紀錄繫於 `employee_id`，重綁只更換 LINE 綁定。新 LINE 帳號可延續原員工身分與歷史紀錄，舊案件編號及處理紀錄照常追查。系統保留綁定及管理者清除綁定的操作紀錄。帳號停用和離職撤權仍適用於兩端。

### 2.3 操作角色與資料範圍

介面可以保留一般使用者與管理者兩類入口。後端分開判定查看、編輯、簽核、匯出及設定權，再套用該角色的資料範圍。一個人可同時擁有多種授權。

| 角色或授權 | 查詢範圍 | 可操作事項 |
|---|---|---|
| 一般員工 | 本人打卡、班表、申請、個資與證照，以及全院行事曆 | 送出補簽、出勤說明、調班、請假、個人資料或證照異動，查看自己的處理進度 |
| 部級主管 | 所管部門及其各級下層單位 | 管理所轄單位，可查看及審核其員工的完整個資。具排班權時可編輯及送審班表 |
| 其他單位管理者 | 受授權的單位 | 管理指定單位，可查看及審核其員工的完整個資。具排班權時可編輯及送審班表，追查單位異常 |
| 案件簽核人 | 分派給本人的案件及審核所需資料 | 核准、退回補件或駁回目前關卡。代理人須有適用的主管指派 |
| 院級主管 | 全院單位 | 管理全院單位，可查看及審核全院員工的完整個資 |
| 人事管理者 | 依授權的單位或全院 | 在授權範圍內查看及審核完整個資，可分別授權人事主檔維護、證照審核、流程設定、月結和關帳後更正 |
| 行事曆管理者 | 全院共用行事曆 | 編輯及發布全院事項、假日及停班資訊 |
| 系統管理者 | 全院單位 | 管理全院單位，可查看及審核全院員工的完整個資。負責清除 LINE 綁定並接收簽核異常通知 |

具個資查閱及審核權的管理角色，在各自的管理範圍內可查閱及審核全部員工個資欄位，包含聯絡資料、身分證字號和住址。個資異動沿用全院統一流程，實際核准依案件關卡分派。請假理由及案件附件依案件權限顯示。權限異動後，網頁與 LINE 的既有登入都依最新授權重新判斷。

### 2.4 行動優先與共用介面

- 以手機與 LINE 內開頁面為主要使用情境。功能頁沿用共用頁首、色彩與卡片樣式，頁面標題旁提供可辨識的返回操作。手機以單欄排列主要控制、內容和狀態。寬螢幕可依容器寬度將控制區與內容並排，保留相同操作順序。
- 共用最小字級為 `1rem`，在預設瀏覽器設定下為 16 px，適用於內文、按鈕、選項、說明、員編及頁尾等可見文字。主要欄位標籤至少為 `1.125rem`，預設為 18 px，使用與區塊標題一致的字重。使用相對字級和可換行的控制與列高，支援瀏覽器文字縮放及相容裝置的系統文字大小。
- 表單與介面控制使用 UI SDK 的標籤、焦點及選取行為。排班單位等項目較多的單選清單，在小型觸控螢幕使用底部選擇面板，桌面在觸發欄位旁展開。面板保留裝置安全區和清單捲動，已選項目以可讀文字、底色與勾號辨識。返回、選單觸發和清單選項等主要觸控目標至少 48 × 48 CSS px。
- 介面保留清楚的鍵盤焦點，選單可用鍵盤開啟、選取及關閉。圖示按鈕有可讀名稱，載入、錯誤及空狀態沿用系統的文字提示。介面動效支援減少動態效果設定。
- 交付前檢查 320 CSS px 窄版、200% 文字放大、桌面鍵盤操作及觸控選取。確認主要內容、控制與焦點可見，並記錄瀏覽器、LINE 顯示情境、相容做法及使用的 Modern Web Guidance 指引。

## 3. 功能需求

### 3.1 上下班打卡、出勤與補簽

- 提供按日期或月份查詢的打卡與出勤一覽，顯示應上班與下班時間、實際打卡、缺卡或遲到早退、已核准調整及待辦狀態。可從出勤結果追溯班表、原始打卡與更正案件。
- 依已生效班表和院方設定的上下班時間窗配對，兩台備援卡機的紀錄一起比對。卡機 ID 與 `punch_state` 保留原始含義，上下班由班次規則判定。卡機連續或重複打卡的配對規則須統一，同一筆事件不得同時充當兩個端點。
- 跨午夜班次回到班表的出勤歸屬日。只有一筆且無法判定屬於上班或下班時，列為待查。尚未排班、打卡尚未同步、員工身分待確認、確定缺卡及免打卡應能分辨。
- 缺卡可申請補簽，已有遲到或早退紀錄可提出說明或更正。主管核准後才更新出勤判定，保留原始打卡時間與更正依據。`history_pending` 或 `unmatched` 的紀錄進入人工查核，不自動歸給候選員工。

### 3.2 班表設定與生效

- 有排班權的人可為責任單位編輯班表。每筆班次至少有員工、責任單位、出勤歸屬日及預定開始和結束時間。常用班別可在實際有需要時做成可重用設定。
- 支援草稿、送審、退回修改、核准及生效。只有已生效班表供出勤與提醒使用。須可辨認同一期間哪份班表有效，並查到變更前的安排。
- 送審與生效時均檢查適用人員和班次重疊。已生效班表的調整走調班或授權更正流程，避免無法追查原班表。

### 3.3 臨時調班與請假

- 共用「請假／調班申請」入口、案件待辦與單位簽核路徑，表單依類型收集資料。
- 調班記錄原班及希望調整的班次。涉及交換班次時，先取得對方確認。核准生效時重新確認原班尚可調整及無重疊，再更新有效班表。
- 跨單位調班維持原本的簽核順序，跨單位本身不重新分派或增設關卡。
- 請假須記錄假別、起迄及受影響班次，可支援整班或部分時間。核准後調整應出勤時間及漏卡提醒。待審案件可依權限撤回，已生效案件依銷假或更正流程處理，再重新計算受影響的班次。假別、可用額度與切算規則由院方定義。

### 3.4 職員查詢、個資及證照

- 支援員工名冊、個人資料卡、部門組織與現任主管、按職稱／職務／聘用類別篩選、在職與到離職清單、人力統計，以及個人與單位分機查詢。個資、學歷與證照依本人或管理角色的資料範圍顯示。
- 員工可提交自己的聯絡資料及證照異動。個資與證照採全院統一審核路徑，核准後才寫回主檔。員工編號、部門、職務、人事狀態與權限交由有權限的人員維護。
- 證照保留有效起迄及續期紀錄。效期未知、尚未生效、有效與已到期各自呈現。無期限須有明確設定。管理者可查待補效期與即將到期項目，確認通知管道後可發出到期提醒。

### 3.5 簽核與流程設定

- 使用一套簽核服務處理送件、待簽、核准、退回補件、駁回及生效。不同案件類型各自執行核准後的業務動作。班表、調班與請假可共用單位流程，個資及證照使用全院統一路徑。補簽使用院方確認後的出勤更正流程。
- 單位流程依 `department.parent_id` 與主管指派逐級上溯。每單位同時間最多一筆有效的正主管或代理主管指派。無直屬員工的單位不單獨列為員工發起單位，若有具簽核權的主管或代理主管，仍保留其上溯關卡。同一人兼任且並非發起人時，合併簽核關卡。
- 路徑必到院級 `department_id = 1`。院級簽核或知會由有設定權的使用者定義。略過下層發起主管本人後，若無下層簽核關卡，院級強制簽核。院級主管以院級身分發起時由本人簽核。
- 送件時保存實際關卡、簽核人和院級動作，後續設定變更用於新案。案件須可追溯每一關的操作者、時間、結果與意見。院級無人承接或送件後需要改派時，先通知系統管理者。完整判定與驗收例見 [人事簽核流程開發規範](approval-workflow.md)。

### 3.6 每月報表與異常管理

- 提供本人及依權限的單位或全院月報。可按月份、單位、員工及問題類型找出未排班、未配對、缺卡、遲到早退、待補正及待簽核項目。
- 報表可追查異常明細、原始打卡與申請結果。補簽、請假或調班生效後重算相關班次，畫面與匯出的資料範圍一致。
- 若啟用月結，應保存結算結果與時間，並讓獲授權的人員重開或登錄更正，保留原結果、變更原因與操作者。工時、加班、請假時間及薪資作業匯出依另訂的業務規則擴充。

### 3.7 全院行事曆

- 全院可查看發布的假日、停班、院內活動及公告。只有具行事曆維護權的人員可變更和發布共用事項。
- 員工可疊加自己的已生效班表及核准請假，單位管理者可在授權範圍內看人力安排。個人請假理由與附件限相關授權人員查看。
- 活動與應出勤規則分開處理。只有明確設定會影響出勤且已發布的假日、停班或例外，才用來調整出勤與提醒。

### 3.8 共用待辦、進度及提醒

- 員工的「我的申請」顯示案件進度、目前關卡、退回原因、核准及生效狀態。主管的「待辦與異常」集中顯示待簽、未分派、待補卡和資料延遲。兩者可由通知連到有權限的案件頁。
- 漏卡提醒須等到該側打卡判定截止，並確認收集及送達進度足以判定。核准請假、停班和免打卡須納入排除。卡機連線時間可供排查，送達延遲或狀態不足時暫緩提醒。提醒應區分缺上班卡、缺下班卡及整班無紀錄待查。
- 同一事件的通知要能去重、記錄結果並重試。LINE 訊息以必要摘要及登入後的連結為主。Email 可作為補充管道，啟用前須有可用聯絡資料。

## 4. 資料需求與共用規則

| 需要保存的資料 | 用途 |
|---|---|
| 醫院帳號與員工身分、可替換的 LINE 綁定、授權操作及單位範圍 | 讓 LINE 與瀏覽器辨識同一位員工，重綁後延續歷史紀錄，並限制查詢、操作與簽核 |
| 班次、班表版本及生效資訊 | 提供出勤對照、調班、月報與歷史追溯 |
| 申請內容、簽核設定、案件實際關卡及處理紀錄 | 保存請假、調班、補簽、人事異動及批准後生效的依據 |
| 院內行事曆與出勤例外 | 顯示院內事項並辨別會影響出勤的假日、停班與免打卡情形 |
| 發送結果與月結紀錄 | 啟用通知及月結時，用於去重、追溯與更正 |
| 班別的人數、職務及證照需求 | 啟用排班檢查時，用於計算人力缺口與查核員工在排班當日的資格 |

- 優先沿用 `hr` 現有人事主檔、證照及打卡資料。出勤異常與效期狀態先由規則計算，保存人為的擬定、核准、更正與需要重現的結算結果。每個新增欄位須能對應到明確用途與維護責任。
- Collector 維持獨立收集，原始打卡保留既有寫入流程。人事應用以授權查詢及業務更正處理出勤。卡機與資料庫架構見 [現行架構](architecture.md)。
- 時間判定與顯示以 `Asia/Taipei` 為準。送件、簽核及核准後的業務生效須具一致性。兩端同時操作或網路重試時，同一關及同一筆業務變更最多生效一次。重新載入後應看到同一筆結果。
- 敏感欄位、案件附件及匯出均須沿用後端存取控制。帳號綁定、授權、改派、核准及結算更正須可由授權人員追查。前端只接收該頁面需要的資料。
- 正式環境與隔離測試環境分開。新結構以 migration 管理，驗證使用合成資料，先確認原始打卡、權限及既有資料可正常運作，再部署正式環境。

## 5. 建議實作順序

1. **打通一個單位的出勤閉環。** 完成登入與權限、單位簽核設定、班表送審及生效、員工打卡查詢、補簽、主管待辦與異常明細。由同一員工使用 LINE 和瀏覽器驗收，並納入跨日班與免打卡案例。
2. **補齊日常人事作業。** 加上調班與請假、員工資料及證照審核、全院行事曆和月報。待請假、停班和同步狀態可辨識後，再上線漏卡與到期通知。
3. **延伸管理用途。** 加入卡機監看與名單差異查核、各班別人數及資格需求、排班缺口和證照覆蓋檢查。確認加班與工時計算規則後，再擴充月結重開、時數彙整及薪資作業匯出。

## 6. 跨功能驗收

| 情境 | 通過條件 |
|---|---|
| 同一員工從 LINE 送件，再用瀏覽器查看 | 兩端顯示同一筆案件、狀態與下一關。重送不產生重複案件或核准效果 |
| 員工更換 LINE 帳號 | 系統管理者清除舊綁定後，員工可用原醫院帳號驗證並綁定新 LINE 帳號。舊 LINE 帳號失去存取權，新帳號仍可查閱原有紀錄 |
| 一般使用者或具主管角色的人嘗試清除 LINE 綁定 | 後端只允許具系統管理者角色的人清除綁定 |
| 系統管理者、院級主管與部級主管審核個資 | 系統管理者及院級主管可管理全院，部級主管可管理所管部門及各級下層。在範圍內的完整個資可供審核，執行核准仍依案件分派 |
| 員工或主管嘗試直接查未授權的人員 | 本人、單位及下層範圍均由後端核對，結果和匯出只含可見資料 |
| 員工跨午夜出勤，兩台卡機均有紀錄 | 依已生效班表的出勤歸屬日與時間窗配對，原始打卡可追查 |
| 班表未核准或異動待審 | 出勤採用當時已生效版本。異動正式生效後才重算相關班次 |
| 兩位員工交換班次 | 雙方確認並完成主管簽核後才更新班表。原班已異動或會造成重疊時列待處理 |
| 漏卡、請假、同步延遲各一筆 | 到判定時間後有足夠資料的確定缺卡才提醒。核准請假排除，延遲列待查。重試只送一次同一事件 |
| 補簽由主管核准 | 出勤與月報更新，案件可追到核准人和原始紀錄 |
| 院級知會、院級簽核、主管本人發起 | 依 [簽核驗收案例](approval-workflow.md#驗收案例) 執行，區分知會與必經的簽核關卡 |
| 員工提交證照異動 | 核准前仍使用原有主檔。核准後效期狀態依新資料計算，證照附件依案件權限顯示 |
| 已發布的全院事項與個人請假同時出現 | 全院可見共用事項，個人及單位安排依權限顯示，請假理由與附件僅限獲授權者 |
| 月結後才核准出勤更正 | 依重開或更正規則更新月報，原結算版本與更正原因仍可追查 |

## 7. 隨各功能開發確認的院內規則

以下細節在開發各自對應的功能時再確認。
- 補簽與遲到說明適用的流程、上下班時間窗與容許時間、兩台卡機的重複事件判定、通知等待時間及歷史打卡歸屬的處理方式。
- 各單位及申請類型的院級動作。簽核與例外處理依 [簽核規範](approval-workflow.md) 執行。
- 假別及時數切算、調班限制、月結日期及重開權限、證照提醒提前天數與通知管道。由院方在各項功能開發時確認適用值與例外。
